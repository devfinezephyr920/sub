# 订阅链接与订阅转换

订阅转换需要先确认输入和目标，clash订阅链接不能只凭名字判断内容，订阅链接转换也不能让未知资料自动兼容。本文把订阅链接、内容形式与客户端入口分别解释；免费订阅链接不在这里得到来源背书或资源交付。

## 地址与地址返回的内容分开核对

地址是取得资料的入口，返回的内容则是客户端需要处理的数据。mihomo 的代理集合文档对 http 来源要求 url，但没有把任意地址都定义为已经可解析的配置。本文没有请求实际订阅，不会用地址存在替代内容记录。

协议资料还有另一种地址语境。HTTP CONNECT 请求目标包含主机与端口，描述的是隧道目标，不等于配置集合的下载入口。两个对象都可能出现在网络资料里，但不能因为都指向远端就互相替换。

客户端的远程配置入口又有自己的处理方式。Verge 把远程订阅输入分成不同方式，FlClash 列订阅地址与本地文件，Shadowrocket 的版本历史也提到订阅导入。每份说明只给自己的应用增加能力，不负责定义所有地址的内容。

因此，记录时至少要区分“拿到什么入口”和“应用期望什么输入”。本文不从链接外观猜协议或内容，不把带某个词的文件名当作格式证明。具体内容未取得，就没有对应解析结论。

本节入口由 [mihomo 官方文档站](https://wiki.metacubex.one/) 与 [Clash Verge Rev 官方文档站](https://clash-verge-rev.github.io/) 表示。它们解释资料怎样组织，不附真实资源，不将文档示例中的任何第三方推广内容带入本文。

## 内容页的三种形式有明确适用范围

mihomo 的代理集合内容页列出 yaml、uri、base64。该页要求三者不要混写于同一文件，URI 与 BASE64 不需要 `proxies:` 字段。这是针对该文档对象的条件，不能删掉对象后称为所有客户端的完整文件规则。

来源类型另有 http、file、inline，讲的是集合如何取得或写入。它与文件内容形式并非同一分类，转换前不能把“从 URL 取得”当成已确认“返回某种格式”。取得方式和表示方式要留两个栏目。

URI 示例出现 ss、vmess 前缀，未提供全部可解析前缀清单。本文不据示例把其他协议都加入，也不把某个协议有出站配置页当成 URI 导入已经明确支持。两个资料页回答不同问题。

同理，BASE64 在这里是页面列出的内容形式。本文不为它补资料中没有的加密、保密或身份保证，也不将形式变换等同服务内容变化。实际输入未读取，就不能宣称转换前后字段一致。

这些边界可以解释为什么转换不能只改文件后缀。页面要求涉及内容对象与目标解析范围，而不是仅一组名字；本文没有提供自动转换工具或无条件转换步骤。确认格式需要实际资料，不由标题代答。

## 转换方法从目标文档可以确认的部分开始

本文的方法是先标明目标客户端，再读它自己的输入说明，然后区分手头内容属于哪种已确认形式。目标没有明确写出的支持范围保持未知，不先把资料塞进某个转换网站。这里没有外部转换服务的来源，因而不列名字或地址。

Verge 的远程方式有地址导入、地址配置及 URL Schemes，本地有新建后导入文件和拖拽文件。它们说明资料怎样进入应用，不是一张所有输入都能自动互转的表。某个入口存在，不证明任意内容能由它处理。

FlClash 的说明确认配置输入既可使用订阅地址，也可采用本地文件，另有编辑器和自定义配置功能。它并未因此为本文给出跨软件的完整字段映射。本文不从编辑能力推断任何来源的文件都可以补改到兼容。

Shadowrocket 明确提到规则文件可从 URL、iCloud Drive 读入，历史说明出现订阅导入。规则文件与订阅在应用资料里分别出现，本文不把两者都称作同一个可转换文件。输入对象缺少确认时，不提供伪造的成功示例。

转换主题因此停在可核对的方法，而非具体服务或命令。读目标、认内容、保留限制是资料整理，不等于已经执行转换。没有对应原文的字段，不在本文增加到输出中。

## 出错时先区分文档限制与实际诊断

若把不同内容形式混在同一文件，已经越过 mihomo 内容页写出的约束。若目标只明确某些入口，却没有完整协议前缀表，则兼容结论仍需确认。这里陈述的是文档边界，不是对任何实际报错已经查明原因。

Verge 的订阅文档提到 client error(Connect) 时可以换另一种导入方式。它还在进一步排错文字中列“允许无效证书”，并标示危险。本文保留这一风险，不把放宽证书校验作为转换的标准步骤，也不以它证明来源可靠。

User-Agent 在同一客户端文档中用于服务端判断客户端类型，再选择下发的配置。本文只说明这个对应关系，不给具体命令或自定义请求头，也不因此推断任何服务的返回内容。未实际取得响应，就没有可写的响应事实。

导入方式、内容限制与请求元数据属于不同层面，不能看到错误就只归为“需要转换”。本文没有收集错误日志或原始文件，因而不列通用报错原因表。页面的排错条目也不等于对当前事件的诊断。

如果需要记录一次结果，应另有目标应用、内容与实际表现等资料。本文没有执行这一过程，所以保持概念说明，不伪造校验输出或成功次数。转换入口不承担实际运行结果的证明。

## URL 内若有凭据，复制地址也会复制那部分

这里讨论的是条件情形：地址中若包含账号凭据，分享完整地址就会把那部分文字一起交出。本文没有实际地址，不展示凭据结构，也不假定所有订阅链接都采用同一认证方式。风险概念不需要一条可工作的资源示例。

地址被交给谁，与内容格式是否匹配是不同问题。一个转换过程即使能处理某种数据，也没有由本文取得它的经营身份、数据用途或删除安排。没有来源的服务不因“转换”这个名称得到隐私承诺。

TLS 1.3 文档说明通道建立后的数据机密性，并指出不会隐藏数据长度。[RFC 8446](https://www.rfc-editor.org/rfc/rfc8446) 所讲的是通道性质，不能被改成接收方经营者不会处理数据的保证。加密传输与接收方声明是两类资料。

本文不解释隐藏身份、规避监管或转交凭据的操作，也不提供在线服务入口。它只保留地址、数据与接收对象之间的概念差别，不将协议定义扩为商家信用结论。实际凭据未在这里收集或处理。

免费与否也不能回答这些问题。转换服务没有标价，不会自动填好数据用途；资源标免费，也不会提供经营资料。本文没有把价格标签当作身份或保密证明。

2016 年研究包含 283 个使用 Android VPN 权限的应用，取自约 140 万应用的语料。本文不使用未确认的百分比，也不借样本数量给当前资源打标签。研究与具体链接之间没有在本文建立对应关系。

Shadowrocket 的应用说明还明确没有把代理服务及服务器资源包括在内。这能说明该应用自己的交付边界，不能拿来给任意订阅的运营者填身份。工具页面、研究样本与资源来源保持不同主语。

本文没有收集公开节点，也没有取得某条外部订阅的运营及条款。所能写的风险边界是资料缺少，不能用免费或能转换替代来源确认。它不构成对某一类资源的统一评价。

不提供列表也意味着本文没有一份已经实际导入的资源记录。没有过程就没有成功声明，没有资料就没有身份声明。相关概念只用于理解输入与转换的问题，不用于包装未知资源。

## FAQ

### 订阅地址就是配置内容吗？

地址是取得资料的入口。本文没有读取实际响应，不能由入口文字确认返回格式。

### YAML、URI、BASE64 可以混在同一文件吗？

mihomo 对应内容页明确不允许混写。这个约束有自己的文档对象，不等于其他软件完整格式定义。

### 改后缀就完成转换了吗？

文档限制涉及内容形式和目标解析。本文没有依据把文件名变化当成内容转换完成。

### 有某个协议配置页就保证其链接能导入吗？

配置页与 URI 解析全貌是不同问题。现有示例没有给出完整前缀支持表。

### 导入错误一定要找转换网站吗？

本文没有诊断实际错误，也没有转换服务的来源资料。客户端文档另有导入方式和风险条目，不能统一归因。

### HTTPS 能证明接收方不处理资料吗？

TLS 文档说明通道机密性。它没有给具体接收方提供经营与数据用途保证。

### 免费订阅在这里被确认过了吗？

没有实际资源或主体记录。本文不把免费标签或历史研究当作链接核验结果。

### 这里能领取 Clash 订阅吗？

不能，本文只解释输入与转换概念。没有节点地址、账号凭据或资源交付。
